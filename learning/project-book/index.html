1. The big picture

DataGuard is a small, dependable command-line tool that audits a CSV file for data-quality problems and produces a human-readable text report plus a structured JSON report describing what it found.

What problem it solves

CSV files used in analysis or machine-learning pipelines often carry quality problems that are easy to miss and expensive to fix downstream:

  • Missing values (empty cells, whitespace-only cells)
  • Duplicate rows or duplicate column headers
  • Constant columns (one distinct value) and all-missing columns
  • Columns whose values mix types (e.g., 88, 95, abc)
  • Rows with the wrong number of fields

DataGuard detects these issues up front so a data engineer or analyst can decide what to fix before loading the file.

Who uses it

Verified README.md: Data Science graduates and junior analysts building software-engineering skills, plus anyone who wants a fast, dependency-free CSV audit that never silently drops data.

Value it provides

  • Never modifies your input file. DataGuard only reads the CSV; it never overwrites or appends to it. (Verified dataguard/cli.py:93-97, 100-104)
  • No third-party runtime dependencies. Only the Python standard library is used at runtime.
  • Surfaces ambiguity instead of hiding it. If a column mixes types, DataGuard reports it as mixed with suspicious examples rather than silently coercing.

Why this matters for a data-science learner

If you're used to loading CSVs into a dataframe and trusting the result, DataGuard shows you why "trust but verify" matters at the ingestion step. Catching 8 missing cells across 4 columns before modeling saves hours of debugging downstream.

Why this separation exists

The profiling engine (profile.py) has no dependency on the CLI and no third-party libraries. It is deliberately side-effect free so it can be unit-tested in isolation. The CLI (cli.py) only handles terminal I/O and file writing.

4. How to run it

All commands below were verified against the real repository.

Prerequisites

Verified pyproject.toml: Python 3.11 or newer. The repository includes a project-local virtual environment at .venv/ (Python 3.12.3) with pytest installed.

Setup

# From the DataGuard project root
cd /home/jabs101/Documents/career-lab/dataguard
.venv/bin/python --version   # Python 3.12.3

Run the tool

# Basic run: profiles a CSV and prints a text report to the terminal
.venv/bin/python -m dataguard samples/clean.csv

# Profile a messy file; JSON report written next to the input by default
.venv/bin/python -m dataguard samples/messy.csv

# Custom text and JSON report paths
.venv/bin/python -m dataguard samples/messy.csv -t messy.txt -j messy-report.json

# Apply required-column and expected-type rules
.venv/bin/python -m dataguard samples/messy.csv \
  --required-columns name \
  --expected-types age=int,score=int

# Write reports to the terminal (use "-" as the target)
.venv/bin/python -m dataguard -t - -j - samples/messy.csv

Run the tests

.venv/bin/python -m pytest

Verified All 50 tests pass (tests/test_cli.py, test_profile.py, test_reports.py, test_edge_cases.py).

No install step needed

DataGuard is not installed as a package; it is run from source via python -m dataguard. The only dependency at runtime is the Python standard library. pytest is a development dependency only.

5. The complete execution journey

DataGuard processes a CSV file through a clear, linear pipeline:

  1. CLI parsing (dataguard/cli.py:build_parser()): Parses command-line arguments, validates required arguments, and prepares report destinations (text and/or JSON). Handles exit codes 0, 1, and 2 as defined in the README.
  2. CSV loading (dataguard/profile.py:load_csv()): Reads the CSV file with standard library csv.reader, strips blank lines, and returns rows as lists of strings. Handles encoding (utf-8-sig by default), invalid paths, non-regular files, and empty files with appropriate exceptions.
  3. Profiling (dataguard/profile.py:profile_rows()): Analyzes each column for missing values, constant values, duplicate headers, ragged rows, type inference, and other quality issues. Returns a ProfileResult object containing all findings.
  4. Rule application (dataguard/profile.py:apply_rules()): Applies user-specified required-column and expected-type rules to the profiling result, generating additional checks and status flags.
  5. Report rendering (dataguard/reports.py): Generates human-readable text and JSON reports from the ProfileResult using stable, deterministic formatting.
  6. Output writing (dataguard/cli.py:main()): Writes reports to specified destinations (terminal, files, or both) while preserving input file integrity. Handles file I/O errors with clear error messages and exit codes.

This pipeline ensures separation of concerns: the profiling engine works in isolation from terminal I/O, and reports are generated from a single source of truth.

Key observations:

  • All processing happens in memory; no files are modified during execution.
  • Type inference is conservative: a column reports one primitive type only when every non-missing cell agrees.
  • Missing values are defined as empty or whitespace-only cells; values like "NA" are not automatically treated as missing.
